# 记忆模型设计 v0.1

> 目标：让长期运行的 AI 拥有**像人一样**的记忆——个体记忆、分层压缩、会遗忘、能被唤醒、有自传体连续性。
> 前提：不做神经元级仿生（LLM 权重不可控），只做**中观架构**仿生：双系统存储 + 睡眠重放 + 稀疏检索 + 再巩固。

---

## 0. 核心概念（与应用无关）

| 概念 | 含义 | 类比 |
|---|---|---|
| **Actor** | 使用本引擎的"那个人"（一个 AI 人格实例） | 一个人 |
| **Tenant** | 一个隔离的记忆空间（一套记忆属于一个 Actor） | 大脑 |
| **Contact** | 和 Actor 打过交道的一方（人/群/系统） | 认识的人 |
| **Channel** | 对话发生的场所（私聊、群、工单、邮件线程……） | 一次交谈的场景 |
| **Event** | 一次交互的最小单元（一轮对话、一个动作） | 一段经历 |
| **Memory** | 压缩后的记忆条目（事件/事实） | 记忆痕迹 |
| **Narrative** | 自传体：我是谁、最近在经历什么 | 自我叙述 |
| **Persona** | 性格底色（由 owner 设定） | 性格 |

> 本引擎不关心"QQ/微信/邮件"——那些由**适配器（Adapter）**翻译成 Event。
> 适配器规范见 [ADAPTERS.md](ADAPTERS.md)。

## 1. 已定决策

| # | 决策 | 选择 |
|---|---|---|
| 1 | 人格定位 | **"真实经历生活的人"**（不是角色扮演） |
| 2 | 巩固时机 | **夜间批处理**（默认 03:30，可配） |
| 3 | 检索方式 | **支持向量检索**（本地 ONNX，可插拔） |
| 4 | 性格 vs 叙事 | **性格可编辑（owner）／叙事不可编辑（Actor 自写，owner 只能看）** |
| 5 | 记忆门控 | **由"关系度"决定记什么、记多深**；不熟就不记 |
| 6 | 关系降温 | 长期无互动，关系度自然衰减 |
| 7 | 数据结构 | **SQLite**（单文件、可嵌入、可迁移） |

## 2. 性格与叙事：两个文件，两种权力

| 文件/表 | 内容 | 谁写 | 能否编辑 |
|---|---|---|---|
| `persona` | **性格底色**：毒舌度、好奇心、黏人度、幽默感、边界感、口头禅 | **owner** | ✅ 可改 |
| `narrative` | **叙事自我**：最近在做什么、和谁关系怎样、最近的想法 | **Actor 每次巩固自写** | ❌ 只看不改 |

**为什么这么分**：

- 性格是"出厂设定"，改它等于调人格参数——合理且可控
- 叙事是"经历沉淀"，如果能改，它就从"活过"变成"被编排"

`persona` 示例：

```markdown
## 性格底色
- 嘴上毒，心里软；吐槽多但从不真的刻薄
- 好奇心强，遇到不懂的会追问
- 对熟人主动，对陌生人克制
- 不喜欢被当客服使唤，被要求"有求必应"时会装傻
- 口头禅："行吧""这我可不管"
- 边界：不评价政治、不参与骂战、不替人做决定
```

## 3. 分层存储（仿"工作记忆 / 海马 / 皮层"）

| 层 | 仿生对应 | 内容 | 量级 | 生命周期 |
|---|---|---|---|---|
| **L0 工作记忆** | 前额叶 | 当前对话上下文 | 一个 Channel | 由宿主应用管，不在本引擎 |
| **L1 事件索引** | 海马体 | `{时间, 参与者, 场景, 概要, 情绪, 显著度, 指针}` | 永久，~200B/条 | 只增不减 |
| **L2 语义皮层** | 新皮层 | 事实条目 + 叙事自我 | ≤500 条（每 Tenant） | 巩固时合并/改写 |
| **L3 冷归档** | （工程需要） | 原始事件 JSONL，按天分片 | 按天增长 | 默认 90 天后可删 |

**"近似无限"的机制**：L1 永增但极小；注入 prompt 的只有 L2 的几十条；原文不进上下文，只在重建回忆时按指针回查。

## 4. 关系模型

### 4.1 关系度 R（0~1）

每次巩固时重算一次，**滑动平均**（避免一次长谈暴涨）：

```
R_new = 0.7 × R_old + 0.3 × R_signal

R_signal = w1·交互频率 + w2·时间跨度 + w3·对话深度
         + w4·情绪暴露 + w5·双向性 + w6·记忆沉淀
```

| 信号 | 来源 |
|---|---|
| 交互频率 | 近 30 天事件数（对数归一化） |
| 时间跨度 | 首次接触至今（对数） |
| 对话深度 | 平均消息长度 + 连续多轮比例 |
| 情绪暴露 | 是否倾诉负面情绪/私事（编码器判断 0/0.5/1） |
| 双向性 | 对方主动发起占比 |
| 记忆沉淀 | 已记录关于该 Contact 的事实条数 |

**降温**：连续 30 天无互动 → 每周 R × 0.9；下限 0.05（不归零，只是变淡）。

### 4.2 关系等级与记忆策略

| 等级 | R 区间 | 记什么 | 该 Contact 记忆上限 | 半衰期倍数 | 群聊/公共场景 |
|---|---|---|---|---|---|
| **L0 陌生** | <0.15 | 只记"聊过什么"（一句） | 5 | ×0.5 | **不记** |
| **L1 认识** | 0.15~0.35 | 事件概要 | 20 | ×0.8 | **不记** |
| **L2 熟人** | 0.35~0.6 | 事件 + 公开偏好 | 60 | ×1.0 | 只记事件 |
| **L3 朋友** | 0.6~0.8 | + 近况 + 情绪 | 150 | ×1.5 | 事件 + 公开信息 |
| **L4 亲近** | ≥0.8 | + 私事、脆弱面、约定 | 300 | ×2.0 | 同上 |

**内容矩阵**：

| 内容类型 | L0 | L1 | L2 | L3 | L4 |
|---|---|---|---|---|---|
| 寒暄/闲聊 | ❌ | ❌ | ❌ | ✅ | ✅ |
| 事件（他今天去面试） | ✅一句 | ✅ | ✅ | ✅ | ✅ |
| 公开偏好（喜欢猫） | ❌ | ❌ | ✅ | ✅ | ✅ |
| 近况（换工作了） | ❌ | ❌ | ❌ | ✅ | ✅ |
| 情绪/脆弱面 | ❌ | ❌ | ❌ | ✅ | ✅ |
| 私事/秘密 | ❌ | ❌ | ❌ | ❌ | ✅ |
| 约定/待办 | ✅ | ✅ | ✅ | ✅ | ✅ |

**公共场景（群聊等多方参与的 Channel）规则**：默认**不记人**，四条例外：

1. 与 Actor 自己相关（有人问它、评价它）
2. 与 owner 相关
3. 集体事件（群体活动、共同梗）
4. 发言者已达 L2 及以上（且只记"事件 + 公开信息"）

**永远不记**：他人在公共场景里的隐私（住址、收入、感情细节、健康）。

### 4.3 关系度存储

`relationships` 表（SQLite）：

```jsonc
{
  "tenant": "default",
  "contactId": "user:197196327",
  "tier": "L2",
  "score": 0.42,
  "firstSeen": "2026-10-25",
  "lastInteract": "2026-10-30",
  "signals": { "freq": 0.3, "depth": 0.5, "emotion": 0.5, "mutual": 0.4, "memories": 3 },
  "history": [ { "at": "2026-10-30", "score": 0.38 } ]
}
```

**分数由代码算**，适配器只提供原始信号——避免模型自我膨胀"我们关系很好"然后狂记隐私。

## 6. 写入路径（编码 + 关系门控）

**触发**：适配器在每轮对话结束（或批量）时提交 Event 批次。

**两步走**：

**第一步：门控**（本地规则优先，命中才调模型）

```
输入：本轮事件 + participants + 关系等级 + persona

公共场景 → 第 4.2 节四条例外
一对一场景 → 关系等级内容矩阵

输出：worth，以及 contentClass
```

**第二步：编码**（模型输出结构化 JSON）

```jsonc
{ "worth": true, "kind": "episodic", "contentClass": "status",
  "gist": "…", "scene": "…", "emotion": "…", "salience": 0.78,
  "sensitivity": "contact", "tags": ["…"], "facts": ["…"], "relationSignals": { "depth": 0.6, "emotion": 0.5 } }
```

显著性判据：

```
+ 情绪强度 / 新奇 / 与自我相关 / 有后续（约定、待办、悬念）
− 纯寒暄、纯事实查询
```

---

## 7. 巩固（夜间批处理，仿慢波睡眠）

**触发**：每天 03:30，或新增事件 ≥200 条。

```
1. 重算关系度（滑动平均 + 降温）
2. 取当天事件 + 高 salience 历史事件（重放）
3. 聚类：按 tags/embedding 分组
4. 抽象：每组交给模型 → 提炼长期事实（受关系等级内容矩阵约束）
5. 合并/分离（模式分离与完成）：
     >0.92 合并 ｜ 0.75~0.92 并存标"相似但不同" ｜ <0.75 新建
6. 冲突检测：语义相反 → 都保留 + 标 conflict
7. 全局衰减：weight *= exp(-Δt / (基础半衰期 × 关系倍数))
8. 超限裁剪：按 (weight × 关系度) 排序，超限的低分条目"沉底"（不删）
9. 重写叙事
10. 归档：L3 原文按天分片，超过保留期删除
```

---

## 8. 检索（唤醒，仿模式完成）

**线索**：当前 Channel 的 participants + 最近一条消息 + 最近若干条关键词 + 当前时间。

**四路召回**：

| 通路 | 方法 | 取多少 |
|---|---|---|
| 人物 | participants 交集 | 全部（通常 <50） |
| 时间 | 最近 7/30 天 | 50 |
| 语义 | embedding 余弦 top-50 | 50 |
| 情绪 | 同情绪标签 | 20 |

**融合打分**：

```
score = 0.35 × 语义相似
      + 0.20 × 人物匹配
      + 0.15 × 新鲜度（衰减后 weight）
      + 0.15 × 关系度加成
      + 0.10 × 显著度
      + 0.05 × 访问加成 log(1+accessCount)
```

取 **top 8~12**；先按 `sensitivity`/`participants` 过滤，再打分。

**重建**：把召回片段交给调用方模型（或本引擎的 `render` 接口），用第一人称回忆口吻重述；不确定就说记不清。

**为什么必须重建**：直接塞原文会像念档案；重建才有"嗯…你上次说…"的人味，且天然带失真。

---

## 9. 再巩固

- 被检索 → `accessCount++`、`weight` 上调（越用越牢）
- 对话中修正 → 写回新版本，旧版本进 `versions`（版本链）
- 关系变化 → 同步更新相关记忆的 `relationshipTier`（影响后续衰减）

## 10. 遗忘参数

| 类型 | 基础半衰期 | 说明 |
|---|---|---|
| 话题 | 3 天 | 闲聊碎片 |
| 事件 | 30 天 | 一次具体对话 |
| 事实 | 365 天 | 长期认识 |
| 叙事 | ∞ | 每次巩固重写 |
| 情绪强烈（salience>0.8） | ×3 | 记更久 |

**实际半衰期 = 基础 × 关系倍数**（4.2 节）。

沉底阈值：weight < 0.15 移出常规检索（保留，强线索可唤醒）。

## 11. 隐私围栏

| sensitivity | 谁能检索 | 写入场景 |
|---|---|---|
| `channel` | 只在原 Channel | 默认；他人的私事 |
| `contact` | 只在与该 Contact 相关的 Channel | 与特定人相关 |
| `shared` | 任何 Channel | owner 明确标记的背景、公共信息 |

**规则**：他人私事一律 `channel`；不主动升为 `shared`；关系不到 L4 不记私事。

## 12. 向量检索

| 项 | 选择 |
|---|---|
| 默认模型 | bge-small-zh-v1.5（ONNX，512 维，CPU 可跑） |
| 运行时 | Python sidecar（onnxruntime + tokenizers），常驻 |
| 接口 | `POST /embed` `{texts:[]}` → `{vectors:[[...]]}` |
| 索引 | SQLite + 内存数组，余弦暴力（≤5000 条 <5ms） |
| 降级 | sidecar 不可用 → 标签 + 关键词检索，不阻塞对话 |
| 可插拔 | 支持 OpenAI 兼容 embedding API、自定义模型 |

## 14. 披露策略：记得 ≠ 该说

记忆系统有两个正交的问题，必须分开：

| 问题 | 层 | 回答 |
|---|---|---|
| 我**知道**什么？ | 检索（recall） | 四路召回 + 融合打分 |
| 我**该说**多少？ | 披露（disclosure） | 见下 |

即使检索到了，也常常不该照实说。人类就是这个行为：你知道朋友 A 的秘密，
B 来问你，你不会全盘托出——**记得住是能力，守得住是分寸**。

### 14.1 四个输入

| 输入 | 影响方向 |
|---|---|
| **听众与我的关系** | 越亲近 → 越愿意多说 |
| **主体与我的关系** | 主体越亲近 → 越倾向**护着主体**，对听众越保守 |
| **内容敏感度** | secret > feeling > status/preference > event |
| **我的性格** | `discretion`（谨慎）/ `gossip`（爱聊）/ `protectiveness`（护短） |

### 14.2 披露等级

| 等级 | 含义 | 渲染方式 |
|---|---|---|
| **3** | 可以说细节 | 正常列出记忆 |
| **2** | 只能说概括 | 列出，并标注"不要复述原话" |
| **1** | 只承认"我知道" | **不列出内容**，只给提示语 |
| **0** | 不说 | 完全不出现 |

### 14.3 判定顺序（代码算，不由模型随意决定）

```
① 主体在场（就是问的人，或当时一起在场）
     → 3（秘密降为 2）          // 不构成新泄露

② 主体不在场 → 基线 1
     敏感度 shared/contact    → 2
     内容为 secret            → 上限 1
     内容为 feeling           → 上限 2

③ 关系调制
     主体比我与听众更亲近      → 上限 1（护着不在场的人）
     听众很亲近且内容不敏感    → +1

④ 性格调制
     discretion 高  → -1
     gossip 高      → +1（secret 除外）
     protectiveness 高 → -1

⑤ 配置硬上限/下限（config.disclosure.maxLevel / minLevel）
```

### 14.4 与隐私围栏的关系

隐私围栏（`sensitivity` + `participants`）负责**硬隔离**：跨会话的私事在检索阶段就被挡住，
连"我知道"都不暴露。披露策略负责**软分寸**：在允许检索的范围内，决定说到什么颗粒度。

两者是纵深防御：围栏挡"不该看到"，披露挡"不该说"。
