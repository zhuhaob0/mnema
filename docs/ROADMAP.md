## 之后（独立项目）

### QQ Bridge 重写

现有 `qq-bridge` 的记忆是内嵌的（`state/social-v2.json`），会重写成：

```
qq-bridge（协议层 + 收发 + 频率控制）
   └─ 调用 mnema（记忆层）
```

要点：

1. 保留协议层（SnowLuma、消息编辑、限流、审计）
2. 记忆相关全部改为 HTTP 调用 mnema
3. 唤醒提示词的记忆段落用 `/v1/recall` 的 `rendered`
4. 角色卡迁到 mnema 的 persona（性格可编辑）
5. 叙事只读展示

> 这是**另一个项目**，本文档只留接口约定（见 ADAPTERS 第 9 节）。

## 技术栈（已定）

| 层 | 选择 | 理由 |
|---|---|---|
| 核心运行时 | **Node.js 24 ESM** | 与 DSH / qq-bridge 生态一致；零原生编译 |
| 存储 | **node:sqlite**（内置） | 零依赖、单文件、可迁移；抽象成 Storage 接口，将来可换 Postgres |
| HTTP | **node:http 手写路由** | 只有 9 个端点，不值得引入框架 |
| 向量 | **Python sidecar**（onnxruntime + tokenizers + bge-small-zh） | 与现有 SenseVoice 环境复用；Node 侧只做余弦计算 |
| MCP | @modelcontextprotocol/sdk（唯一运行时依赖） | 保证与各类 MCP 客户端兼容 |
| 测试 | node:test | 内置，无需框架 |
| 配置 | JSON 文件 + 环境变量覆盖 | 简单可审计 |

**依赖策略**：除 MCP SDK 外零运行时依赖。原生模块（sqlite/onnx）全部走"内置"或"sidecar"，避免装环境时踩编译坑。

## 从现有 qq-bridge 继承的好东西

重写 qq-bridge 时，这些设计值得原样搬过去（都是踩过坑换来的）。

### 安全与权限

| 机制 | 为什么值得抄 |
|---|---|
| 会话级 agentToken | 每个会话独立令牌，天然防跨会话注入；我们在 relay 才开唯一的受控口子 |
| ownerQQ 单点判据 | 手机控制、发说说、传话全部以 ownerQQ 为准，与白名单解耦，权限表一眼看懂 |
| 白名单 + allowAllWhenEmpty | 默认关闭、显式列出；空列表行为要有明确文档 |
| 敏感词审计 | 出站内容过一遍，防止令牌/密钥被模型说出去 |
| 出站内容守恒检查 | 记录发送前后条数/字节数，异常可回溯 |

### 稳定性

| 机制 | 为什么值得抄 |
|---|---|
| 单实例锁 + 优雅退让 | 避免双开抢端口，认领外部实例而不是硬起第二个 |
| 看门狗 + 指数退避重启 | 崩了自动拉起，2s → 4s → 8s，上限 2 分钟 |
| sendChain 串行队列 | 保证"先文字后表情/图片"的真人顺序，并发调用不乱序 |
| 幂等设计 | 会话映射、巩固按天标记；失败重试不重复写 |
| 超时看门狗 | 实测遇到过后台进程干完活挂住 15 分钟不退出 |

### 可观测性

| 机制 | 为什么值得抄 |
|---|---|
| health.json 定期落盘 | 不看日志也知道现在卡在哪 |
| 有界轮转诊断日志 | 只留最近 N 行，避免无限增长 |
| activity 摘要 | 一眼看出最近在跟谁聊、说了什么 |
| 控制台 console-token | 本地管理入口，与 agent token 分离 |

### 提示词工程（最值钱的一块）

| 技巧 | 效果 |
|---|---|
| 分条与节奏（一条=一个意群，多数 ≤30 字） | 避免小作文，像真人打字 |
| 反 AI 味清单 | 减少客服腔 |
| 不要求有求必应（可以装傻/拒绝/已读乱回） | 主体性 |
| 首答前静默 / 沉睡前观察 | 模拟"等你说完"的节奏 |
| 行为化的工具描述（看群/打字发送） | 让模型把工具当动作而不是 API |
| 结构化记忆类别 | 比一段自由文本更可控 |

### 工程习惯

| 习惯 | 说明 |
|---|---|
| 每个补丁留 .bak-* 备份 + 文档编号 | 升级上游后能逐条核对 |
| 排错文档按症状组织 | PITFALLS.md 那种索引方式很好用 |
| 权威源 vs 生成物分离 | 改源再生成，禁止直接改生成物 |
| 写文件前先校验路径 | 我们的 .gitignore 就写错过一次目录 |
